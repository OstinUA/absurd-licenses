**契約書さながらの重々しさで起草された、ソフトウェアライセンスのパロディ全14点。もう限界を迎えた開発者の優先順位に基づいている。**

本リポジトリは、型破りでユーモラス、そして風変わりな「ライセンス様の」文書を収集したものである。これらは馴染み深いソフトウェアライセンスの形式的な構造を借り受け、それを理不尽な要求に適用している。太陽運行への遵守、家族への電話の義務化、契約上の先延ばし、過剰な著作者表示、そして調達部門の注目を集めるはずのトークン単価などである。

各ライセンスは独立した UTF-8 の `.txt` ファイルであり、タイトル、前文、使用・複製・改変を規定する条項、そしてそれぞれの不条理さに合わせて仕立てられた免責条項を含む。すべての本文は英語で書かれており、カタログの順序に沿って番号が付けられている。

> **これは風刺作品集である。** これらの文書は架空の起草演習であり、法的な吟味を経た文書ではない。その制限的条件を、通常のオープンソース許諾として提示してはならない。Time-Restricted ライセンス内に現れる「MIT」という語は、条件付きパロディの一部であり、全文を通常の MIT ライセンスにするものではない。強制力の評価や認証は一切主張していない。

## 各ライセンスの役割

### 01. 「見るだけ・触るの禁止」ライセンス（Look-But-Don't-Touch）

[全文](../licenses/01-look-but-dont-touch.txt)

想像しうるあらゆる権利を誇張して留保する。公開されていることは存在を確立するだけで、いかなる相互作用も許諾しない。唯一の積極的許諾はタブを閉じることであり、生涯の露出上限は10秒である。クローン、フォーク、スクリーンショット、頭の中での再構築、就寝前の意図的な想起について、明示的に規定している。

免責条項は、好奇心、頭から離れない思考、そして忘れ難いことが判明した変数名について、一切の責任を負わないとしている。

### 02. 受け身攻撃型ライセンス（Passive-Aggressive）

[全文](../licenses/02-passive-aggressive.txt)

幅広い再利用許諾が、義務的な沈黙と共存する。利用者は自身のフォークを維持できるが、Issue を立てたり、バグ報告を送ったり、アーキテクチャを批判したり、著作者に依頼されていない Pull Request を提出したりしてはならない。著作者は特定の一件の貢献を招くことができ、それによって恒久的なフィードバック窓口を開設したことにはならない。

免責条項は、コードがひどいものであることを著作者が以前から認識していた事実を記録し、それ以上の証拠を聞く義務がそこから生じることを否定する。

### 03. LLM禁止 / AIポイズンライセンス（No-LLM / AI-Poison）

[全文](../licenses/03-no-llm-ai-poison.txt)

タンパク質でできた人間には、個人利用および商用利用の無償許諾が与えられる。自動的な抽出、解析、学習、embedding、評価、および同様の取り込み行為は、トークンあたり100万ドルの課金に対する企業としての同意を構成する。再処理は別途課金対象となり、モデルを削除しても架空の請求書は消えない。

人間向けの機械的な表示と保存、および実行可能ファイルを生成する目的のみの通常のコンパイルは、自動化利用のトリガーから明示的に除外される。これらの操作を取り込み目的に転用した時点で除外は終了する。ポイズン留保条項は、意味的に不都合な素材を許容する。免責条項は、自信たっぷりの戯言と、スープと取り違えられたアルゴリズムを対象とする。

### 04. フードウェアライセンス（Food-Ware）

[全文](../licenses/04-food-ware.txt)

有益な結果は、ささやかなもてなしの義務を生じさせる。次に適切な対面の機会において、利用者は著作者にピザ、ビール、またはコーヒーをおごる。食事制限に配慮した代替品や、双方が合意したリモートでの同等物も認められる。誰も会合を手配する必要はなく、双方の地理的条件が不便なうちは、未処理の義務に利息は付かない。

飲食1回分で、その利用者によるそのバージョンの利用に関する義務は決済される。コーヒーを買っても、無制限のサポートは買えない。

### 05. 時間制限付きライセンス（Time-Restricted）

[全文](../licenses/05-time-restricted.txt)

本ソフトウェアが一時的に寛容になるのは、日付が奇数の木曜日、GMT の 14:00（含む）から 16:00（含まない）の間のみである。本ライセンスは、時間の経過に依存するという架空の構造の中に、見覚えのある MIT 形式の許諾と免責条項を含んでいる。

時間帯の外では複製と改変が禁止される一方、実行はインスタンスごとに開始1分あたり50米ドルを要する。前もってダウンロードしておいても恒久的な許諾は保持されない。アイドル状態の実行中プロセスはカウントされ、休眠状態の保存コピーはカウントされない。免責条項は、16:01 に完了するビルドに対して特に同情を示さない。

差異が解消されない場合、この手順は繰り返される。免責条項は、記憶された成功と、別のマシンがそれを再現するという約束とを区別する。

[全文](../licenses/07-vampire.txt)

リモートサーバーと分散ノードは、それぞれの実際の地理的位置に従う。極夜は考慮される。極昼は、他のプロジェクトに取り組むための延長された機会を提供する。免責条項は、コウモリへの変身や、朝食と両立するデバッグを保証することを拒否する。

### 08. シュレーディンガーライセンス（Schrödinger's）

意図的な構文エラーや警告の抑制は、誠実な観測として扱われない。その後のリビルドは初期の結果を変更できない。インタプリタ型プロジェクトでは、同等の初回検証を用いる。本物の猫は付属しない。

### 11. 先延ばし屋ライセンス（Procrastinator's）

### 12. 依存地獄ライセンス（Dependency Hell）

## パロディライセンスファイルの準備

1. 一覧から完全な `.txt` の本文を選ぶ。
2. それをパロディ用またはデモ用のプロジェクトに `LICENSE.txt` として複製する。
3. `[YEAR]` と `[AUTHOR NAME]` のすべての出現箇所を一貫して置換する。エゴブーストライセンスでは、必須のコミット文言の中にもその名前が使われる。
4. タイトル、バージョン、前文、条項、免責条項をまとめて保持する。不条理な条件を削除すると、文書は実質的に別物になる。
5. 成果物はカスタムの風刺ライセンスとして説明すること。Time-Restricted ライセンスを単に「MIT」と表記したり、全文が与えていない条件を示唆するために一般的な標準ライセンス識別子を使ったりしてはならない。

たとえば、リポジトリのルートディレクトリで PowerShell を使う場合：

```powershell
Copy-Item -LiteralPath .\licenses\04-food-ware.txt -Destination .\LICENSE.txt
```

このコマンドはテンプレートを複製するだけである。完成した文書として提示する前に、そのプレースホルダーを置換すること。このコレクション自体が、読み手が選んだパロディを自動的に取得することはない。個々の条項は文学的な内容であり、本リポジトリのコントリビューター向けの運用指示ではない。

## 細かい文言を読む

- **「奇数の木曜日」の定義は一つだけ：** 日付が奇数の木曜日を指す。隔週のスケジュールではない。
- **稼働中の1分は高額になりうる：** Time-Restricted ライセンスは開始された1分ごとに課金するため、時間帯の外では1秒でも、1インスタンスにつきすでに50米ドルが発生する。
- **日没はマシンに準拠する：** 本人が暗闇の中にいても、白昼のリモートサーバー上での実行が許可されることにはならない。
- **最初のビルドは最初のまま：** クリーンなリビルドでも、ビルド成果物の削除でも、シュレーディンガーの観測はリセットされない。
- **2週間とは実際の遅延を意味する：** トラッカーで締切を移動しても、先延ばし屋の義務は履行されない。
- **1か月とは暦月を意味する：** 「死んだプロジェクト」ライセンスは、一律30日の期間で代替することを認めない。
- **パッチはマージされなくてよい：** カルマライセンスは真剣な提出をもって足りるとし、メンテナーの応答をコントリビューターの統制外に置く。
- **普遍的な互換性の保証は存在しない：** 二つのパロディを組み合わせると、本文が明示的に書き直されない限り、双方の要求がそのまま残る。したがって、夜行性プロジェクトについて昼間のみ開かれる会議は、異常に慎重な計画を要することになるかもしれない。

- 独立した UTF-8 の `.txt` ファイルを用い、一覧の番号付き命名規則を維持すること。
- タイトル、前文、明示的な許諾または禁止、複製と改変の条件、そしてそれぞれの性質に合わせて仕立てられた保証免責と責任制限を含めること。
- ライセンスの文章は形式的・精確・感情的に抑制されたものとすること。笑いは実効的な条件に担わせること。
- トリガーは、読み手が遵守と創造的な再解釈を区別できる程度に明確に定義すること。
- 一覧、説明文、リポジトリツリー、ライセンス数のバッジはまとめて更新すること。

コレクションを読むのにビルドシステムは不要である。いかなる依存地獄も、読み手が個人的に受け取ると決めるまでは、該当する本文の中に留まる。
