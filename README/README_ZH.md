**十四份完整的软件许可证戏仿文本，以合同般的庄重口吻起草，并秉持一位忍无可忍的开发者的价值排序。**

本仓库收集了一系列不落俗套、充满幽默感、形态奇特的“许可证式”文本。它们借用常见软件许可证的正式结构，并将其套用于种种无理要求：遵从日照规律、强制给家人打电话、写进合同的拖延症、铺天盖地的署名要求，以及足以引起采购部门关注的 token 定价。

每一份许可证都是一个独立的 UTF-8 编码 `.txt` 文件，包含标题、序言、约束使用、复制与修改的条款，以及针对其特定荒诞之处量身定制的免责声明。所有许可证文本均为英文，并按目录顺序编号。

> **这是一部讽刺作品集。** 这些文件是虚构的起草练习，并非经过审定的法律文书。其限制性条款不应被当作常规的开源许可来呈现。“Time-Restricted”许可证中出现的 “MIT” 一词属于附条件戏仿的组成部分；它并不会使完整文本成为一份普通的 MIT 许可证。我们不对其可执行性作出任何评估或认证。

## 各许可证说明

### 01. “只许看，不许碰”许可证（Look-But-Don't-Touch）

[完整文本](../licenses/01-look-but-dont-touch.txt)

对一切可以想象的权利进行夸张的保留。公开可得只确立了它的存在，并不允许任何交互。唯一被明确授予的许可是关掉标签页，且终身暴露时间上限为十秒。克隆、fork、截图、在脑海中重建，以及睡前刻意回想，均被逐条明确规定。

免责声明拒绝对好奇心、挥之不去的念头，以及那些怎么也忘不掉的变量名承担责任。

### 02. “被动攻击型”许可证（Passive-Aggressive）

[完整文本](../licenses/02-passive-aggressive.txt)

宽泛的复用许可与强制性的沉默并存。用户可以维护自己的 fork，但不得提交 Issue、发送 bug 报告、批评架构，或向作者提交未经请求的 Pull Request。作者可以邀请某一次特定的贡献，而这并不意味着常设一个反馈部门。

免责声明记录了作者早已知道代码很糟糕这一事实，并否认因此负有任何听取更多证据的义务。

### 03. “禁用 LLM / AI 投毒”许可证（No-LLM / AI-Poison）

[完整文本](../licenses/03-no-llm-ai-poison.txt)

由蛋白质构成的人类可获得免费的个人及商业使用授权。自动化的提取、解析、训练、embedding、评测以及类似的摄取行为，即构成企业方对每 token 一百万美元费用的认可。重复处理将另行计费，而删除模型并不会删除那张虚构的账单。

为人类进行的机械式展示与存储，以及仅为生成可执行文件而进行的常规编译，明确不会触发自动化使用条款。一旦将这些操作转用于摄取，上述豁免即告终止。投毒保留条款允许包含在语义上令人不适的内容；免责声明涵盖自信满满的胡说八道，以及被误当成汤的算法。

### 04. “食物酬谢”许可证（Food-Ware）

[完整文本](../licenses/04-food-ware.txt)

一个有用的结果会产生一份小小的招待义务。在下一次合适的当面相遇时，用户须请作者吃一份披萨、喝一杯啤酒或一杯咖啡。饮食上的替代选择以及双方共同接受的远程等价方式也在允许之列。谁都不必刻意安排会面，并且在双方地理位置仍然不便往来期间，这笔待履行的义务不会产生利息。

一份茶点即可结清该用户对该版本的使用义务。买一杯咖啡并不等于买到了无限支持。

### 05. “限时许可”许可证（Time-Restricted）

[完整文本](../licenses/05-time-restricted.txt)

本软件仅在日期为奇数的星期四、GMT 时间 14:00（含）至 16:00（不含）之间临时变得宽松可用。该许可证在其虚构的时间相关结构之中，包含一份可辨识的 MIT 式授权与免责声明。

在该时间窗口之外，复制与修改均被禁止，而执行则按每个实例每开始一分钟 50 美元计费。提前下载并不会保留永久许可。空转的运行中进程计入收费；处于休眠状态的存档副本不计入。免责声明对那些在 16:01 才结束的构建尤其毫无同情。

### 06. “在我机器上能跑”许可证（Works-On-My-Machine）

[完整文本](../licenses/06-works-on-my-machine.txt)

作者庄严的历史性陈述确立了唯一的参考环境。在其他任何地方出现的失败，都将成为用户自身的环境差异。在责怪本软件之前，用户必须重装操作系统、更换硬件并更换互联网服务商——即便这是一个完全离线运行的程序。

如果差异仍然存在，则重复上述流程。免责声明区分了“记忆中曾经成功”与“承诺另一台机器也能复现这种成功”。

### 07. “吸血鬼”许可证（Vampire）

[完整文本](../licenses/07-vampire.txt)

执行、编译、调试以及积极的开发活动，仅允许在当地时间日落到日出之间进行。窗帘、云层、墨镜和深色模式均不具有合同效力。休眠状态的副本可以撑过白天；正在运行的任务必须在黎明时停止。

远程服务器和分布式节点遵循其实际所在的地理位置。极夜会得到照顾；极昼则为你提供了投入其他项目的宽裕机会。免责声明拒绝保证任何蝙蝠变形，也不保证调试过程能与早餐兼容。

### 08. “薛定谔”许可证（Schrödinger's）

[完整文本](../licenses/08-schrodingers.txt)

在第一次编译之前，许可状态处于未坍缩的叠加态。一次真实的首次尝试报错，会使项目坍缩为免费使用。首次尝试即成功且无任何警告，则为该项目产生一次性 5 美元的付款义务。构建成功但确有警告，同样免费；尝试被中断而没有结果，则状态保持未定。

故意制造的语法错误与压制警告的行为，不算作诚实的观测。之后的重新构建无法改变最初的结果。解释型项目采用等效的首次验证。本许可证不附带任何真实的猫。

### 09. “家庭 / 奶奶”许可证（Family / Grandma）

[完整文本](../licenses/09-family-grandma.txt)

非商业用途可自由使用。免费的商业开发要求每一位参与的开发者，至少每七天与其母亲、祖母、其他近亲，或自选家庭中合适的一员，完成一次真实的语音或视频通话。

机器人、未接来电、短信，以及公司宣称“大家都是相亲相爱的一家人”的说法，均不符合条件。合规并不需要录制通话内容，也不需要向作者发送任何个人数据。免责声明预见了那些不请自来的人生建议，以及帮忙修打印机的请求。

### 10. “自我膨胀”许可证（Ego-Boost）

[完整文本](../licenses/10-ego-boost.txt)

署名信息必须占据应用的主屏幕，且有效字号不得小于 72 个排版点（pt）。“关于”页面、一条 tooltip，或者一个被缩放到看不见的超大标签，都不足以满足要求。没有常规界面的产品必须提供合适的展示安排。

在引入了本软件的仓库中，每一条新的 commit 都必须包含一句规定好的、赞颂作者天才的语句，机器人提交、merge 和 revert 也不例外。已有的历史记录无需重写。免责声明涵盖被耗尽的屏幕空间，以及对产品首要用途的不幸误判。

### 11. “拖延症患者”许可证（Procrastinator's）

[完整文本](../licenses/11-procrastinators.txt)

授权始于一项不可撤销的承诺：交付一个有实质意义的项目里程碑，且至少迟满十四整天。原始截止日期必须在使用之前记录下来；事后再修改日历不算作真正的迟到。一份基本完成的“预览版”仍然算作交付。

一次符合条件的里程碑失约即满足该项目的义务。之后的进一步拖延纯属自愿。免责声明不对启动会议、客户的失望，或那些本来就已经过于乐观的估算承担任何责任。

### 12. “依赖地狱”许可证（Dependency Hell）

[完整文本](../licenses/12-dependency-hell.txt)

每一个采用本软件的项目都必须刻意添加十个互不相同的过时 npm 或 pip 包作为直接依赖。每个包都必须与集合中的另一个成员冲突，且整个集合必须构成一张连通的互不兼容网络。这些包必须参与真实的构建或执行路径，其版本与冲突情况须有记录。

偶然引入的传递依赖和并未使用的示例 manifest 文件不符合条件。把冲突解决掉将中止许可，直到恢复足够的混乱为止。免责声明认为一次失败的安装可能是合规的绝佳证据。

### 13. “因果报应”许可证（Karmic）

[完整文本](../licenses/13-karmic.txt)

发现一个可复现的 bug，即产生在七天内提交一份具有实质内容的修复 Pull Request 的义务。一个 Issue 或一句抱怨不能替代补丁。提交即已足够；贡献者无需掌控维护者是否 merge 的决定。

一个逾期未修的 bug 会带来一份不可转让的因果失衡，其执行方式包括打翻咖啡、找不到钥匙，以及诸如此类的小小不便。迟到的补丁可以面向未来地治愈这种失衡，但无法让洒出去的咖啡倒流回杯中。作者对用户的因果状况不承担任何责任。

### 14. “死掉的项目”许可证（Dead Project）

[完整文本](../licenses/14-dead-project.txt)

## 准备一份戏仿许可证文件

1. 从目录中选定完整的 `.txt` 文本。
2. 将其复制到目标戏仿或演示项目中，命名为 `LICENSE.txt`。
3. 一致地替换 `[YEAR]` 以及每一处 `[AUTHOR NAME]`。“自我膨胀”许可证还会在其强制性的 commit 语句中用到该姓名。
4. 将标题、版本号、序言、条款与免责声明一并保留。删去那些荒诞条件会实质性地改变这份文件。
5. 将结果描述为一份自定义的讽刺性许可证。不要把“限时许可”许可证简单标注为 “MIT”，也不要使用人们熟悉的标准许可证标识符去暗示完整文本并未授予的条款。

例如，在仓库根目录下使用 PowerShell：

```powershell
Copy-Item -LiteralPath .\licenses\04-food-ware.txt -Destination .\LICENSE.txt
```

该命令只是复制一份模板；在把它作为成品文件出示之前，请先替换其中的占位符。本合集自身并不会自动适用读者所选中的那份戏仿许可证。其中的各项条款属于文学内容，而不是本仓库贡献者的操作指南。

## 细读小字条款

- **“奇数星期四”只有一个定义：** 指日期数字为奇数的那个星期四。它不是单双周轮换的时间表。
- **运行中的一分钟可能代价高昂：** “限时许可”许可证对每一个已开始计算的一分钟收费，因此在窗口之外哪怕只有一秒，单个实例也已产生 50 美元费用。
- **日落以机器所在位置为准：** 你本人身处黑暗之中，并不授权你在白昼之下的远程服务器上执行。
- **第一次构建永远算第一次：** 无论是干净的重新构建，还是删除构建产物，都不会重置薛定谔的观测结果。
- **两周指的是真正的迟到：** 在跟踪工具里挪动截止日期，并不构成对“拖延症患者”许可证义务的履行。
- **一个月指的是一个日历月：** “死掉的项目”许可证不接受用统一的三十天间隔来替代。
- **补丁不必被合并：** “因果报应”许可证只要求认真提交即可，维护者的回应不在贡献者的掌控范围之内。
- **不存在通用的兼容性承诺：** 把两份戏仿许可证组合在一起，两套要求都会保留，除非明确改写文本。因此，一场只在白天举行、讨论夜间项目的会议，可能需要异常周密的安排。

## 贡献

欢迎就本合集提交 Issue 和 Pull Request。“被动攻击型”许可证描述的是其虚构的采用方作者；它并不禁止针对本选集提出编辑意见。

新增条目或修订时：

- 使用独立的 UTF-8 编码 `.txt` 文件，并保留目录中带编号的命名约定。
- 包含标题、序言、明确的许可或禁止事项、复制与修改的条件，以及量身定制的保修免责与责任限制条款。
- 让许可证行文保持正式、精确、情绪克制。把笑点交给那些具有实际效力的条款去承担。
- 把触发条件定义得足够清晰，让读者能够区分“合规”与“创造性再解读”。
- 同步更新目录、说明文字、仓库目录树，以及许可证数量 badge。

阅读本合集不需要任何构建系统。任何依赖地狱都留在相应的文本之中，直到某位读者选择把它当成针对自己的人身攻击为止。
